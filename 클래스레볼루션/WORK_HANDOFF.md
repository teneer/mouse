# 클래스레볼루션 — ChatGPT Work 인수인계

> 기준일: 2026-11-16 (KST)  
> 저장소: https://github.com/teneer/mouse  
> 작업 브랜치: `class-revolution`  
> 프로젝트 경로: `클래스레볼루션/`

## 1. 이 문서의 목적

이 문서는 현재 채팅에서 시작한 클래스레볼루션 프로젝트를 ChatGPT Work로 넘기기 위한 기준 문서다. Work는 이 문서와 `docs/` 아래의 세부 문서를 먼저 읽고, 현재 브랜치의 실제 코드를 확인한 뒤 작업해야 한다.

**현재 구현은 초기 골격이다. 완성품이나 브라우저 검증을 통과한 버전으로 간주하지 않는다.**

## 2. 프로젝트 목표와 확정된 사용자 요구

- 하나의 학급 운영 앱에 **전자칠판, 개인·모둠·학급 점수 통합관리, 체크리스트**를 포함한다.
- 과제/과제 제출·평가 관리는 후속 단계다. 이번 초기 개발에서 과제 모듈을 먼저 만들지 않는다.
- 화면을 나란히 나누는 분할 화면이 아니라, 제공된 영상처럼 **메뉴를 눌러 각 모드를 전체 화면으로 전환**한다.
- 어느 모드에 있든 다른 브라우저 탭에서 점수가 바뀌면 공통 팝업 피드백을 볼 수 있어야 한다.
- 초기 저장은 로컬 DB 우선이다. 같은 PC의 여러 브라우저 탭 사이에서 변경을 실시간으로 전달한다.
- 데이터 JSON 백업과 복원을 제공한다.
- 사용자가 첨부한 이미지·아바타·사운드·영상 자료를 적극 활용한다.
- 전자칠판은 저장소의 `만능칠판-test/` 6.0.0을 기반으로 하되, 원본 폴더는 수정하지 않는다. 독립 실행 가능한 `클래스레볼루션/` 안에 복사본을 둔다.
- 기존 영상의 사용 흐름은 참고하되, 클래스레볼루션의 전체 UI는 새로 구성한다.

## 3. 반드시 지킬 작업 경계

1. 모든 변경은 `class-revolution` 브랜치의 `클래스레볼루션/` 안에서 한다.
2. `main`, `만능칠판-test/`, `만능칠판2/` 등 원본 폴더를 직접 수정하지 않는다.
3. 분할 화면으로 회귀하지 않는다. 전자칠판·점수판·학급 성장·체크리스트는 전체 화면 모드 전환이다.
4. 현재 코드의 점수 규칙은 잠정 구현이다. 레거시 앱의 수식과 새 점수 엔진이 다르므로 `docs/DEVELOPMENT_BACKLOG.md`의 정책 결정을 먼저 확인한다.
5. 영상에 등장하는 룰렛·사다리타기 등은 참고 영상에 보인 기능일 뿐, 이번 필수 범위로 승인된 것이 아니다. 사용자 확인 없이 필수 기능으로 확장하지 않는다.
6. 사용자가 나중에 하기로 한 과제 관리를 앞당기지 않는다.
7. 브라우저에서 실제로 실행·검증하지 않은 기능을 완료했다고 보고하지 않는다.

## 4. 현재 저장소 상태

2026-11-16 초기 구현의 기준 커밋은 `1babb08ab55d98de5c1cb7661e19a4d29b54c90c`이다. 이 문서 작성 후 추가되는 문서 커밋은 GitHub 브랜치 이력을 확인한다.

- `modules/whiteboard/`: `만능칠판-test/`의 6.0.0 소스 복사본. 기존 점수판 패널을 숨기는 `board-only.css`와 클래스레볼루션용 제목 변경을 추가했다.
- `core/`: IndexedDB, 탭 이벤트 버스, 점수 엔진, 전역 피드백.
- `modules/scoreboard.js`: 학생 명단 붙여넣기, 개인 점수, 모둠 합계의 초기 구현.
- `modules/growth.js`: 별길 10칸의 기여가 모이면 학급 점수 1점으로 전환하는 초기 구현.
- `modules/checklist.js`: 체크·기호·1~5점·숫자 입력의 날짜별 기록 초기 구현.
- `assets/audio/`: 사용자 첨부 사운드 9개.
- `assets/visuals/` 및 `assets/avatars/`: 이미지 에셋을 연결하도록 코드가 참조하지만, 현재 브랜치에 실제 이미지 파일은 아직 배치되지 않았다.

**검증 상태:** 현재까지 GitHub에 소스와 문서를 커밋했지만 실제 브라우저 실행 검증은 하지 않았다. 특히 전자칠판 iframe, 자산 경로, 모드 전환, 다중 탭 피드백, 백업/복원은 실제 테스트가 필요하다.

## 6. 다음 작업의 권장 순서

1. 현재 브랜치의 코드와 문서를 다시 읽고 실제 파일 상태를 확인한다.
2. 첨부 원본 ZIP에서 에셋을 추출·분류하고, 기존 코드의 경로에 맞게 배치한다. 원본 ZIP은 보존한다.
3. 로컬 HTTPS/localhost에서 앱을 실행해 치명적 오류와 잘못된 경로를 먼저 해결한다.
4. 전자칠판을 전체 화면 모드로 구동하고, 기존 점수판 패널이 중복 노출되거나 불필요하게 초기화되지 않는지 검증한다.
5. 점수 데이터 모델과 학급 성장 전환 규칙을 정리한다. 특히 감점·직접 조정·되돌리기 정책은 추측으로 확정하지 않는다.
6. 학생·모둠 관리와 체크리스트를 실제 수업에서 사용할 수준으로 완성한다.
7. 다중 탭·전역 피드백·백업/복원·새로고침 후 데이터 유지까지 QA한다.

## 7. 참고 자료의 성격

- `docs/PROJECT_BRIEF.md`의 사용자 요구는 확정 요구로 취급한다.
- 영상은 기존 앱의 사용 흐름과 화면 동작을 보여주는 참고 자료다. 영상 속 모든 기능이 현재 개발 범위라는 뜻은 아니다.
- 기존 `index.html`·`app.js`·`style.css`는 레거시 대시보드 참고 소스다. 새 앱의 현재 구현이 아니다.
- 첨부 ZIP은 원본 에셋 묶음이다. 개별 파일의 실제 배치·사용 여부는 현재 저장소를 기준으로 다시 확인한다.

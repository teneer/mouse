# 만능칠판 2.0 — 리팩토링 1차 구현본

첨부된 원본 6개 파일을 기준으로 기존 툴바 색상, 버튼 모양, 팁업과 모달 스타일을 재사용한 정적 웹앱입니다.
실제 브라우저 E2E 테스트를 마친 출시판은 아닙니다. 배포 전에 `BROWSER-CHECKLIST.md`를 확인해주세요.

## 배포 방법

1. 기존 GitHub 저장소에서 작업 브랜치를 만들고 원본을 커밋/태그로 보관합니다.
2. ZIP 안의 `index.html`, `만능칠판.html`, `style.css`, `script.js`, `data.js`, `history.js`, `clipboard.js`, `js/`와 `.nojekyll`을 **현재 앱이 배포되는 폴더**에 넣습니다. JS 파일 일부만 교체하면 안 됩니다.
3. **기존 `CNAME`, 도메인 DNS, GitHub Pages 설정, `.github/` 배포 워크플로는 삭제하거나 바꾸지 않습니다.** 이 ZIP에는 사용자 도메인 값을 추측해 넣은 CNAME이 없습니다.
4. 빌드 단계 없이 기존 정적 배포 방식으로 배포합니다. `package.json`은 선택적인 로컬 테스트용이며 런타임 설치는 필요하지 않습니다. 기존 저장소에 package.json이 있으면 덮어쓰지 말고 필요한 테스트 설정만 병합합니다.
5. `index.html`과 기존 `만능칠판.html`은 같은 앱을 엽니다. 기존 한글 주소를 없애거나 강제로 리다이렉트하지 않았습니다.
6. 기존 탭을 닫고 새 버전을 열어 강력 새로고침합니다. 기존에 서비스 워커를 별도로 설치했다면 그 서비스 워커의 캐시 갱신도 필요합니다. 이 구현은 서비스 워커를 추가하지 않습니다.
7. 먼저 테스트 배포에서 확인한 후 주 배포 브랜치에 반영합니다. 테스트 주소와 실제 주소는 저장소가 다를 수 있으므로 실제 주소에서 데이터 가져오기를 별도로 확인해야 합니다.

로컬에서 실행할 때는 `file://`로 열지 말고 다음처럼 HTTP 서버를 사용합니다.

```sh
python -m http.server 8000
```

이후 `http://localhost:8000/`을 엽니다. 시스템 클립보드 버튼은 HTTPS 또는 localhost 보안 컨텍스트와 사용자 권한이 필요합니다.

## 변경 범위

### 제거했습니다.
- 레이어 선택·가시성·잠금·대상 레이어 관리 UI와 편집 로직을 제거했습니다.
- 스케줄 UI, 타이머, 일정 실행 및 새 버전의 일정 저장소를 제거했습니다.
- 호환성 가져오기에서만 구버전 객체의 `customLayer` 속성을 제거합니다. 구버전 DB 자체를 삭제하지 않습니다.

### 유지했습니다.
- 배경색과 사용자 지정 색상을 사용할 수 있습니다.
- 펜과 자유 텍스트를 사용할 수 있습니다. 텍스트를 더블클릭하면 다시 편집할 수 있습니다.
- 줌 범위는 10%~1,000%입니다. 휠은 커서 위치를 기준으로, 버튼은 화면 중심을 기준으로 줌합니다.
- 선택/이동 버튼, Space를 누른 채 드래그, 마우스 가운데 버튼으로 화면을 이동할 수 있습니다.
- 홈 버튼은 문서의 고정된 중심으로 돌아가며 100% 배율로 바꿉니다.
- 자동저장과 페이지별 언두/리두를 제공합니다.
- 저장 화면과 불러오기를 유지합니다. 안전을 위해 저장 화면은 현재 페이지를 덮어쓰지 않고 **새 페이지로** 불러옵니다.

### 수정·추가했습니다.
- 형광펜은 색상과 굵기를 선택할 수 있으며 불투명도는 32%입니다. 여러 획을 겹치면 더 진해집니다.
- 객체 지우개는 클릭/드래그로 만나는 객체를 통째로 지웁니다. 빠르게 이동할 때 포인터 이벤트 사이의 객체가 건너뛰어질 수 있습니다.
- 영역 지우개는 드래그한 사각형과 **경계 상자**가 겹치는 객체를 통째로 지웁니다. 투명한 여백이나 회전된 객체의 경계 상자도 포함될 수 있습니다.
- 그룹은 지우개에서 하나의 객체입니다. 선택한 객체만 지우기와 현재 페이지 전체 지우기도 제공합니다.
- **픽셀 일부/획 일부를 깎는 지우개는 구현하지 않았습니다.** Fabric 5 기본 배포본에 없는 EraserBrush를 존재하는 API처럼 사용하지 않았습니다.
- Shift+클릭/선택 드래그 후 그룹·언그룹할 수 있습니다. 그룹은 Ctrl/Cmd+G, 언그룹은 Ctrl/Cmd+Shift+G입니다.
- 페이지 생성·선택·복제·이름 변경·삭제를 제공합니다. 페이지 순서 재배치, PDF 내보내기, 서버 계정 동기화는 이 구현의 범위가 아닙니다.
- 같은 브라우저 프로필, 같은 출처(스킴+호스트+포트), 같은 배포 폴더의 탭끼리 동기화합니다. 다른 브라우저, 시크릿 창, 다른 기기와는 동기화하지 않습니다.

## 파일 가져오기

- PNG/JPG/GIF/PDF를 캔버스에 드롭하거나 더 보기 → 이미지·PDF를 선택합니다.
- 파일 합계는 한 번에 40MB까지입니다.
- PNG/JPG/GIF는 브라우저에서 정지 PNG로 변환합니다. GIF 애니메이션은 재생하지 않습니다.
- 6,400만 픽셀을 초과하는 이미지는 거절하며, 이미지의 긴 변은 최대 3,072픽셀로 축소합니다. 해상도 원본 보존이 필요하면 별도로 원본 파일을 보관해주세요.
- PDF는 최대 50쪽/파일, 한 번에 전체 100개 이미지까지 처리합니다. PDF.js로 쪽별 렌더링 후 이미지로 만들고 **현재 칠판 페이지에 세로로 배치**합니다. PDF의 각 쪽을 칠판 페이지로 자동 분리하는 방식은 아닙니다.
- PDF 긴 변은 최대 2,048픽셀입니다. PDF 벡터/텍스트/링크/폼 편집과 원본 PDF 보관 기능은 없습니다.
- 암호가 있는 PDF에는 암호 입력 창을 표시합니다. 암호는 저장하지 않습니다.
- 가져오기 취소 버튼은 가능한 다음 처리 지점에서 취소합니다. 완료 전에는 캔버스에 부분 배치하지 않습니다. 대형 이미지 디코딩은 즉시 취소되지 않을 수 있습니다.
- PDF 변환은 브라우저 안에서 수행하며, 파일 바이트를 서버로 업로드하는 코드는 없습니다. 단, CDN에서 PDF.js와 보조 글꼴/CMap 파일을 다운로드할 수 있습니다.

## 시스템 클립보드

- 앱 전용 메모리 클립보드가 시스템 붙여넣기를 가로채는 구조를 없앴습니다.
- Ctrl/Cmd+C·X·V는 native copy/cut/paste 이벤트를 사용합니다.
- 복사 버튼은 OS 클립보드에 PNG, text/plain, 가능한 경우 편집 가능한 데이터가 담긴 text/html을 기록합니다.
- 이미지/그룹을 복사할 때 HTML 안에도 PNG 미리보기를 포함합니다. 다만 외부 앱마다 선택하는 형식과 HTML 정제 규칙이 달라 동일 동작을 보장하지 않습니다.
- 앱 사이의 붙여넣기는 HTML의 편집 데이터가 보존되면 편집 가능한 객체/그룹으로 복원합니다. 여러 객체를 복사하면 하나의 그룹으로 붙이며 언그룹할 수 있습니다.
- 외부 앱이 편집 데이터를 제거하면 PNG나 텍스트로 붙여넣습니다. URI 목록이나 웹페이지 이미지를 원격 URL로 가져오지는 않습니다.
- text/html 쓰기를 지원하지 않는 브라우저에서는 PNG 복사를 재시도하며 알림을 표시합니다. 권한 거부 시 Ctrl/Cmd+C·V를 사용해주세요.
- 복사 이미지의 긴 변은 최대 4,096픽셀입니다. 큰 선택 묶음은 나누어 복사해야 합니다.
- 텍스트 편집 중에는 브라우저의 텍스트 복사·붙여넣기를 방해하지 않습니다.

## 저장, 페이지, 동기화

- 새 DB는 `WhiteboardPagesDB:<배포 폴더 경로>`입니다. 원본 `WhiteboardAppDB`와 별개입니다.
- 편집 후 350ms 지연으로 저장을 시작하고, IndexedDB 트랜잭션이 완료된 뒤 저장 완료를 표시합니다. 저장 중 추가 편집이 생기면 후속 저장을 수행합니다.
- 숨김 전환 시 저장을 시도하고, 저장 대기/진행 중 탭을 닫으면 beforeunload 경고를 요청합니다. 브라우저 강제 종료/OS 중단 시 마지막 미완료 편집의 저장까지 보장할 수는 없습니다.
- 저장 공간 부족/권한 오류 시 저장 실패를 표시합니다. JSON 백업은 자동저장에 실패한 현재 캔버스도 포함하도록 작성했습니다.
- DB의 페이지 레코드별 버전을 readwrite 트랜잭션 안에서 비교합니다. 다른 페이지 수정은 각 레코드에 독립 저장됩니다.
- 같은 페이지의 저장 버전이 다르면 기존 원격 페이지를 덮어쓰지 않고 내 작업을 `(충돌 복구)` 페이지로 추가합니다. 이는 자동 객체 병합이나 실시간 공동 커서 방식이 아닙니다.
- 삭제는 tombstone 레코드로 남겨, 다른 탭의 미저장 수정이 조용히 사라지지 않도록 합니다.
- BroadcastChannel로 작은 변경 신호만 전달하고 실제 내용은 IndexedDB에서 읽습니다. storage 이벤트와 5초 주기 재확인을 보조 수단으로 사용합니다.
- 편집/텍스트 입력/드로잉/모달 작업 중에는 원격 화면을 덮어씌우지 않습니다. 작업 종료 후 다음 알림 또는 재확인 때 반영합니다.
- 페이지 선택과 뷰포트는 탭의 sessionStorage에 보관하므로 다른 탭의 화면을 강제로 이동시키지 않습니다.
- 저장 화면 목록은 모달을 열 때 다시 읽습니다. 모달이 이미 열려 있을 때 다른 탭에서 저장 화면을 추가/삭제했다면 닫았다가 다시 열어주세요.
- 언두/리두는 페이지별 최대 40개, 직렬화 문자열의 추산 크기 최대 24MiB를 기준으로 오래된 기록을 제거합니다. 단일 최신 상태가 이 크기를 넘으면 그 상태 하나는 유지합니다.
- 언두/리두 자체도 자동저장·동기화합니다. 뷰포트 이동은 언두 기록에 넣지 않습니다. 새로고침/원격 페이지 갱신 후에는 해당 기록을 초기화합니다.
- 객체 전체 지우기는 언두할 수 있지만 페이지 삭제와 저장 화면 삭제는 언두할 수 없습니다. 마지막 페이지는 UI에서 삭제하지 못하게 했습니다.

## 저장 화면 미리보기 기준

썸네일은 현재 확대/이동 상태나 객체 전체 경계에 맞추어 만들지 않습니다.
저장할 때의 브라우저 캔버스 크기를 `frame.width/height`로 기록하고, 문서의 고정 중심 `frame.cx/cy`에서 **홈 위치·100% 화면**을 렌더링한 뒤 가로 320픽셀로 축소합니다.
따라서 홈 화면 밖에 있는 객체는 미리보기에서도 보이지 않습니다. 서로 다른 화면 비율에서 저장한 썸네일은 여백이 달라질 수 있습니다.

## 이전 데이터와 백업

- 새 버전을 처음 열면 새 빈 페이지를 만듭니다. 구버전 데이터를 자동으로 수정하거나 삭제하지 않습니다.
- 더 보기 → 이전 데이터는 같은 출처의 `WhiteboardAppDB`에서 자동저장과 저장 화면을 **읽기 전용으로** 가져옵니다.
- 이전 자동저장은 새 페이지가 되고, 이전 저장 화면은 불러오기 목록에 추가됩니다. 객체의 분류 속성은 제거하고 모든 객체를 보이게 만듭니다. 원래 숨긴 객체도 다시 보일 수 있습니다.
- 원본 캔버스 4,800×3,200의 중심 좌표인 (2,400, 1,600)을 이전 데이터의 홈 중심으로 사용합니다.
- 구버전 일정 데이터는 읽거나 실행하지 않습니다. 원본 DB에 남아 있을 뿐 새 앱에서는 쓰지 않습니다.
- 외부 URL 이미지, 이미지 필터, 패턴/그라디언트 채움, 캔버스 배경 이미지/마스크가 있는 특수 백업은 가져오기를 거절합니다. 원본 파일과 원본 DB를 보관한 상태에서 이미지 파일 등으로 변환해야 합니다.
- 더 보기 → JSON 백업은 전체 페이지와 저장 화면을 파일로 내려받습니다. 백업 가져오기는 기존 내용을 덮어쓰지 않고 새 항목으로 추가합니다. 2.0 백업 형식, 파일당 100MB까지 지원합니다.
- 많은 PDF/저장 화면을 포함하면 내보낸 파일이 100MB를 넘을 수 있습니다. 그런 대형 데이터의 분할 백업/복원 UI는 구현하지 않았습니다. 대규모 자료를 넣기 전 작은 데이터로 백업·복원을 시험해주세요.
- 앱 자동저장은 클라우드 백업이 아닙니다. 사이트 데이터 삭제, 브라우저 저장소 정리, 프로필 변경, 도메인 변경에 대비해 JSON 파일을 별도 보관해야 합니다.


## 검사 결과와 한계

- JavaScript 문법 검사와 HTML ID/로컬 import 참조 검사를 수행했습니다.
- `node --test tests/*.test.mjs`로 핵심 로직/CanvasTools 모형 테스트 22개가 통과했습니다. 외부 npm 패키지는 필요하지 않습니다.
- 실제 Fabric.js 렌더링, IndexedDB 브라우저 구현, OS 클립보드, PDF.js 워커, 모바일 터치는 이 테스트에서 실행하지 않았습니다.
- 이 실행 환경에서는 외부 CDN 접속과 브라우저 E2E 검증이 불가능했습니다. **22개 테스트 통과를 모든 기능의 실기기 동작 보증으로 해석하면 안 됩니다.**
- 기존처럼 Fabric.js 5.3.1을 CDN에서 로드합니다. PDF 가져오기 때 PDF.js 4.10.38을 지연 로드하며 `isEvalSupported:false`를 사용합니다. 이 버전들이 최신이라는 의미는 아닙니다.
- 오프라인 캐싱, CDN 파일 자체 호스팅, SRI 추가는 이번 구현에 포함하지 않았습니다. CDN 차단 환경에서는 vendor 배포가 별도로 필요합니다.

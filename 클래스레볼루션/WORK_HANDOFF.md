# 클래스레볼루션 — 개발 인수인계

기준일: 2026-11-18 KST · 저장소: https://github.com/teneer/mouse · 브랜치: `main` · 작업 폴더: `클래스레볼루션/`

## 현재 방향

원본 클래스123 영상·스크린샷의 화면과 사용 흐름을 충실히 구현한다. 초기 문서의 “새로운 UI” 방향은 폐기했다. 학생카드/자리배치/학생관리 → 학급점수 → 체크리스트 순으로 진행하며 전자칠판은 현재 메뉴에서 제외했다. 원본에 보여도 사용자가 요청하지 않은 기능은 추가하지 않는다.

상세 기준·영상 시간대·자산 위치·브라우저 검증·남은 차이는 [원본 화면 복원 기록](docs/REFERENCE_RESTORATION.md)을 먼저 읽는다. 다음으로 기존 9개 문서와 실제 코드를 대조한다.

## 작업 경계와 확정 정책

- `main`에서 `클래스레볼루션/` 안의 변경만 커밋·푸시한다. 다른 만능칠판 폴더는 수정하지 않는다.
- 전체 화면 모드 전환, 로컬 IndexedDB, 같은 브라우저의 다중 탭 연동을 유지한다. 서버 저장은 별도 과제다.
- 한 번의 점수 적용에는 모든 대상에게 같은 사유·같은 점수 변동량을 사용한다.
- 개인/학급점수판은 상세연출, 명렬은 사유·변동량·대상 전체가 들어가는 하단 팝업이다. 수신 탭의 모드에 맞춘다.
- 감점 때 캐릭터가 기뻐하지 않는다. 2프레임 캐릭터 파일은 상점 연출, 단독 캐릭터는 평상시와 감점에 사용한다.
- 개인 감점에 따라 별길이 한 걸음씩 뒤로 가며, 황금알 경계를 넘으면 황금알을 줄이고 기존 기여 학생을 복원해 후퇴한다. 별길만 별도로 차감하지 않는다.
- 체크리스트 Score/체크는 개인점수와 별개다. 해당 값/체크된 학생을 선택하고 개인점수를 지정하여 수동 지급한다. 자동 보상·자동 환수는 없다.
- 자리배치는 전체 180도 방향 전환, 학생·모둠 이동과 교환을 지원한다.
- 불명확한 정책은 사용자가 결정한다. 실제 검증한 범위만 완료로 보고한다.

## 실제 코드

- `core/score-composer.js`: 대상, 사유, 한 명당 변동량, 최근/즐겨찾기, 원자적 일괄 점수 적용.
- `core/score-engine.js`, `growth-path.js`: 점수와 성장/황금알/후퇴 이력을 한 트랜잭션으로 처리.
- `modules/scoreboard.js`: 카드·자리배치·학생/모둠 편집·학생 휴지통/복원·명단 붙여넣기·점수 이력.
- `modules/growth.js`: 원본 별길·황금알, 상점/감점 이동, 학급 이름·목표/보상 설정.
- `modules/checklist.js`: 네 기록 형식, 날짜·통계·항목 편집/보관/복원, 대상 선별과 수동 지급.
- `restoration.css`: 원본 화면 비율과 스프라이트 참조. 기존 app/stage1/growth CSS 뒤에 적용.
- `modules/whiteboard/`: 보존된 독립 복사본. 현재 앱에서 로드하지 않는다.
- `assets/`: 사운드9개, 시각자료21개, 움직임 아바타70종×2크기, 정지 아바타 시트.

## 다음 단계

먼저 현 버전과 원본 장면을 함께 확인한다. 점수 이력 되돌리기, 목표 달성 연출, 원본 나무 단계는 남아 있다. 모바일·삼성브라우저와 실제 교실 기기의 터치·해상도 검증도 별도 수행한다. 과제 관리와 영상의 미요청 도구는 앞당기지 않는다.

현재를 원본 전체 기능의 완성판으로 간주하지 않는다. 무엇을 구현했고 무엇을 실제 브라우저로 확인했는지는 복원 기록의 표를 기준으로 한다.

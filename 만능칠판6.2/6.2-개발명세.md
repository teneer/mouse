# 만능칠판 6.2 개발 명세

작성 기준: 2026-11-18
기준 소스: 만능칠판 6.1, main 커밋 \`81a2414de8d74288e8ece156faecf2f28efa9413\`

## 0. 범위와 보호 원칙

- 개발 위치는 \`/만능칠판6.2/\`입니다.
- \`/만능칠판6.1/\` 및 \`/만능칠판-test/\` 원본은 수정하지 않습니다.
- 6.1을 기능 기준선으로 삼고 필기·페이지·점수판·도형·이미지/PDF·화면 전송·기기/탭 관리·객체 관리 등 기존 기능을 보존합니다.
- 6.2는 6.1의 최종 대체 버전을 목표로 합니다. 실제 전환은 자동 테스트와 브라우저/Firebase 실기기 검증 후 판단합니다.
- 기존 Firebase 학급 데이터 승계를 기본으로 합니다. 같은 Firebase 프로젝트와 공유 칠판 ID를 사용할 경우 기존 서버 데이터가 공유될 수 있으므로, 서버 스키마 변경 전 백업과 하위 호환성 계획을 마련합니다.
- 경로 기반 IndexedDB/localStorage는 6.1과 분리합니다. 로컬 데이터는 6.2 전용 저장 공간을 사용합니다.
- 이 문서는 설계 명세입니다. 명시적으로 구현을 지시하기 전까지 문서 갱신만으로 코드가 구현된 것으로 간주하지 않습니다.

## 1. 사용 모드와 연결 상태

### 1.1 기본 모드: 서버 모드
- 정상 접속 시 서버 모드로 시작합니다.
- Firebase의 공유 칠판 데이터가 정본입니다.
- 연결된 온라인 기기와 탭은 실시간으로 서버 상태를 공유합니다.
- 서버 모드에서 편집하려면 서버 연결이 정상임을 확인해야 합니다.

### 1.2 서버 모드에서 연결이 끊긴 경우
- 자동으로 로컬 모드로 바꾸지 않습니다.
- 편집·점수 조작·객체 이동·페이지 변경 등 서버에 반영되는 조작을 즉시 차단합니다.
- 화면에 \`오프라인에서는 편집할 수 없습니다. 잠시 후 다시 시도해주세요.\`를 표시합니다.
- 사용자가 로컬 모드로 전환하지 않는 한 서버 모드를 유지하고, 연결 복구를 기다립니다.
- 연결이 끊기기 전에 이미 생성된 서버 전송 요청은 온라인일 때와 같은 정책으로 계속 재시도합니다. 단, 연결이 끊긴 뒤 새로운 편집 요청을 생성하지 않습니다.
- 재시도 요청은 동일한 작업 ID를 유지해 중복 반영을 막습니다.
- 연결 복구 후 미확정 요청의 서버 처리 여부를 확인하고, 서버의 확정 상태를 다시 받은 뒤 편집을 허용합니다.
- 네트워크 연결 표시만으로 온라인을 확정하지 않습니다. 실제 Firebase 읽기/쓰기 연결과 서버 응답을 확인합니다.

### 1.3 로컬 모드로 전환
- 연결 단절 안내에서 사용자가 로컬 모드를 선택했을 때만 로컬 편집을 허용합니다.
- 전환 순간 현재 기기가 마지막으로 확인한 데이터를 6.2 전용 로컬 작업 공간으로 복사합니다.
- 서버 모드의 미확정 전송 대기열은 취소하고, 해당 기기에서 이후 서버 편집 요청을 보내지 않습니다.
- 이미 서버에 도착했는지 불확실한 요청은 작업 ID로 추적하되, 과거 작업 로그를 로컬 변경 기록으로 누적하거나 재생하지 않습니다. 재연결 시 서버 정본을 확인한 뒤 로컬 최종 데이터와 비교합니다.
- 로컬 모드에서는 점수, 되돌리기, 필기, 객체, 페이지, 설정 등 기존 기능을 독립적으로 사용할 수 있습니다.
- 여러 기기가 동시에 각각 로컬 모드로 전환하는 것을 허용합니다. 한 기기만 오프라인 작업을 담당하도록 제한하지 않습니다.
- 인터넷이 복구되어도 로컬 모드에서 자동으로 서버 모드로 전환하지 않습니다. 데이터 비교 및 후보 처리 절차를 거칩니다.

### 1.4 모드별 편집 가능 여부

| 모드 | 서버 연결 | 편집 | 서버 전송 |
|---|---|---|---|
| 서버 모드 | 정상 | 가능 | 즉시 전송 |
| 서버 모드 | 끊김 | 불가 | 기존 미확정 요청 재시도 |
| 로컬 모드 | 끊김 | 가능 | 없음 |
| 로컬 모드 | 복구 | 가능 | 해시 비교 후 최종 스냅샷 후보만 제출 |

## 2. 온라인 동시 편집과 충돌 처리

### 2.1 기본 원칙
- 서로 다른 객체는 여러 기기에서 동시에 편집할 수 있습니다.
- 동일 객체는 한 번에 한 기기만 제어합니다.
- 같은 객체를 다른 기기에서 클릭하면 나중에 클릭한 기기가 제어권을 가져옵니다.
- 객체 속성별 병합은 기본 방식으로 사용하지 않습니다. 독점 제어권으로 같은 객체의 동시 수정을 방지합니다.
- 공유 작업은 서버가 확정한 순서를 기준으로 모든 기기에 반영합니다.

### 2.2 객체별 제어권
- 객체마다 안정적인 객체 ID를 기준으로 제어권을 관리합니다.
- 제어권 소유자는 안정적인 기기 ID와 탭 ID로 식별합니다. 표시 이름은 식별자로 사용하지 않습니다.
- 다른 기기가 동일 객체를 클릭하면 서버가 클릭 요청을 순서대로 확정하고, 새 요청이 제어권을 획득합니다.
- 기존 소유 기기는 해당 객체의 선택 상태와 편집 핸들을 즉시 해제하고 편집을 종료합니다.
- 다중 선택 중 일부 객체의 제어권을 빼앗기면 해당 객체만 선택 해제합니다. 나머지 객체의 선택과 제어권은 유지합니다.
- 서로 다른 객체의 제어권은 독립적이므로 PC가 객체 A를, 태블릿이 객체 B를 동시에 편집할 수 있습니다.
- 제어권 이전 시 이미 서버에서 확정된 변경은 보존합니다. 확정되지 않은 드래그/크기 조절의 임시 미리보기는 취소하고 마지막 확정 상태로 되돌립니다.
- 텍스트 입력 중 다른 기기가 같은 객체를 클릭해 제어권 이전이 요청되면, 기존 소유 기기의 현재 입력 내용을 강제 완료합니다. 입력 취소나 편집 전 원문 복원은 하지 않습니다.
- 제어권 이전 순서는 `기존 입력 강제 완료 → 최종 텍스트 서버 확정 → 기존 편집 종료 → 새 기기에 제어권 부여`입니다. 서버는 최종 텍스트 확정을 확인하기 전에 새 소유자에게 편집 권한을 부여하지 않습니다.
- 새 소유 기기는 서버에서 확정된 최신 텍스트를 받은 뒤 편집을 시작합니다. 한글 IME 조합 중인 입력도 조합을 마무리해 현재 표시된 입력 내용을 확정한 뒤 넘깁니다.
- 모든 객체 변경 요청은 현재 제어권 토큰을 포함해야 합니다. 제어권을 잃은 기기의 늦은 변경 요청은 서버에서 거부합니다.
- 제어권은 선택 해제, 페이지 이동, 편집 종료, 탭/기기 종료 시 해제합니다.
- 객체가 선택된 상태로 유지되는 동안 해당 기기/탭의 제어권을 유지합니다. 선택 상태가 유지되는 한 주기적으로 임대(lease)를 갱신하며, 단순히 시간이 지났다는 이유로 제어권을 빼앗지 않습니다.
- 사용자가 선택을 해제하거나 페이지를 이동하거나 편집을 종료하면 제어권을 해제합니다.
- 비정상 종료나 연결 단절로 해제 신호를 받지 못한 경우에는 갱신 신호가 끊긴 뒤 임대가 만료되면 서버가 제어권을 회수합니다. 임대 만료는 선택 중인 정상 탭의 제어권을 빼앗기 위한 제한이 아니라 비정상 종료를 정리하기 위한 안전장치입니다.
- 두 기기가 거의 동시에 같은 객체를 클릭하면 서버가 먼저 확정한 클릭을 기준으로 소유권을 정합니다. 뒤에 확정된 클릭은 다시 제어권을 가져갑니다.

### 2.3 객체 삭제와 페이지 삭제
- 객체 삭제는 전역 변경입니다. 삭제가 서버에서 확정되면 모든 온라인 기기에서 즉시 객체를 제거합니다.
- 다른 기기에서 해당 객체를 편집 중이어도 별도 잠금이나 사전 허가를 요구하지 않습니다.
- 삭제된 객체를 선택 중인 기기는 선택 상태·편집 핸들·텍스트 편집 상태를 즉시 해제합니다.
- 페이지 삭제도 같은 원칙을 적용합니다. 다른 기기에서 해당 페이지를 보고 있거나 편집 중이어도 삭제가 확정되면 해당 페이지가 모든 온라인 기기에서 사라집니다.
- 페이지 삭제를 위해 페이지 전체를 사전 잠그거나 다른 기기의 편집을 기다리지 않습니다.
- 삭제된 객체/페이지의 ID와 버전(삭제 표식 또는 세대 번호)을 관리해 늦게 도착한 이전 편집 요청이 삭제된 대상을 되살리지 못하게 합니다.
- 삭제 이후 도착한 오래된 객체 편집·페이지 편집 요청은 서버에서 거부합니다.
- 서버 모드에서 연결이 끊긴 기기는 편집할 수 없으므로 서버 삭제를 놓친 상태에서 계속 서버 편집하는 상황을 허용하지 않습니다. 로컬 모드로 전환한 기기는 독립 데이터이므로 로컬 페이지가 남을 수 있으며, 재연결 시 후보 데이터 비교 절차로 처리합니다.

### 2.4 점수판 작업
- 점수 증감(+/-)은 최종 숫자 전체를 덮어쓰지 않고 증감 작업으로 처리합니다.
- 여러 기기에서 동시에 발생한 증감은 서버 확정 순서대로 모두 누적합니다. 예: 10점에서 PC +3, 태블릿 +2가 확정되면 최종 15점입니다.
- 각 증감 요청에는 고유 작업 ID를 부여해 재시도 시 중복 가산/감산을 방지합니다.
- 점수 변경 이벤트와 애니메이션은 서버 확정 순서를 따릅니다.
- 절대값 직접 수정(예: 10점을 20점으로 입력)은 증감보다 우선합니다.
- 같은 점수에 직접 수정과 증감이 동시에 요청되면 서버가 직접 수정 작업을 우선 확정해 새로운 기준값을 설정합니다. 겹쳐 들어온 증감은 이전 기준값에 적용하지 않고, 직접 수정 확정 후 새 기준값에 서버 확정 순서대로 적용합니다. 증감 요청을 임의로 버리거나 중복 적용하지 않습니다.
- 직접 수정 중에는 같은 점수의 다른 직접 수정은 동시에 확정하지 않고, 직접 수정이 끝난 뒤 서버 순서에 따라 처리합니다.

### 2.5 되돌리기/다시 실행
- 되돌리기 가능한 작업은 기기별 이력이 아니라 모든 온라인 기기가 공유하는 서버 확정 순서로 관리합니다.
- 어느 기기에서 되돌리기를 실행하더라도 전체 작업 순서에서 가장 최근의 되돌리기 가능한 확정 작업을 대상으로 합니다.
- PC에서 작업한 뒤 태블릿에서 작업했다면, PC에서 되돌리기를 눌러도 태블릿의 더 최근 작업이 먼저 취소될 수 있습니다.
- 되돌리기/다시 실행도 서버에서 순서와 작업 ID를 확정하고 모든 기기에 공유합니다.
- 직접 점수 절대값 수정은 기존 합의대로 되돌리기 대상에서 제외합니다.
- 삭제된 객체/페이지를 되돌리기로 복구할 때에는 새 버전으로 복원하며, 과거 지연 이벤트가 복구된 대상을 덮어쓰지 않도록 합니다.

### 2.6 페이지 구조와 전역 설정
- 페이지 추가·삭제·순서 변경은 서버가 확정한 순서대로 모든 기기에 반영합니다.
- 페이지 삭제는 2.3 규칙을 따르며 다른 기기의 편집을 기다리지 않습니다.
- 배경, 격자, 페이지 표시 설정 등 같은 설정 항목을 여러 기기에서 변경하면 서버에서 마지막으로 확정된 값이 적용됩니다.
- 서로 다른 설정 항목의 변경은 서로 덮어쓰지 않도록 항목 단위로 처리합니다.

### 2.7 파일/이미지 객체
- 이미지/PDF 객체의 이름·위치·크기·선택·삭제 등 메타데이터 편집은 해당 객체의 제어권을 따릅니다.
- 실제 이미지/PDF 바이너리 전송은 객체 편집 제어권과 분리하고 기존 수동 P2P/WebRTC 방식을 유지합니다.
- 파일이 없는 기기에서도 객체의 메타데이터를 관리할 수 있습니다.
- 파일 교체/삭제 시 오래된 파일 전송이 최신 파일을 덮어쓰지 않도록 파일 버전 또는 콘텐츠 식별자를 확인합니다.

## 3. 로컬 모드 재연결과 스냅샷 후보

### 3.1 해시 우선 비교
- 로컬 모드 기기가 온라인으로 복귀해도 자동으로 서버 모드로 전환하지 않습니다.
- 로컬의 정규화된 공유 데이터에 SHA-256 콘텐츠 지문을 계산하고 해시값을 먼저 서버에 전달합니다.
- 서버 정본과 해시가 같으면 스냅샷을 업로드하지 않습니다. 해당 기기는 서버 정본과 동일하므로 서버 모드로 복귀할 수 있습니다.
- 기존 임시 후보 그룹과 해시가 같으면 스냅샷을 다시 업로드하지 않고 해당 데이터 그룹에 기기만 등록합니다.
- 서버 정본 및 모든 기존 후보와 다른 해시일 때만 최종 스냅샷을 임시 후보로 제출합니다.
- 여러 기기가 동일한 새 데이터를 갖고 있으면 첫 기기만 스냅샷을 제출하고 나머지는 같은 그룹에 합류합니다.
- 과거 점수 이벤트, 편집 이벤트, 되돌리기 이벤트를 하나씩 재전송하거나 서버에 누적하지 않습니다. 로컬 최종 결과만 스냅샷으로 제출합니다.

### 3.2 데이터 지문 범위
- 지문에는 공유 정본을 구성하는 페이지 순서/이름/내용, 객체 속성, 점수, 모둠, 공유 설정 등 실제 공유 데이터를 포함합니다.
- 기기 이름, 탭 이름, 온라인 상태, 커서 위치, 화면 뷰포트 등 기기별 임시 정보는 제외합니다.
- 정규화와 직렬화 규칙을 고정해 같은 데이터는 기기와 브라우저가 달라도 같은 SHA-256을 생성해야 합니다.
- 이미지/PDF 바이너리는 Firebase 스냅샷에 포함하지 않습니다. 파일 참조·메타데이터는 공유 데이터에 포함하고, 실제 파일 동일성은 파일별 콘텐츠 식별자로 별도 확인합니다.
- 기존 데이터에 지문이 없으면 최초 한 번 정규화 및 지문 계산을 수행합니다.

### 3.3 임시 후보 그룹
- 서버 정본과 각 기기의 로컬 최종 데이터는 서로 다른 후보가 될 수 있습니다.
- 동일한 지문을 가진 서버/기기 후보는 하나의 선택지로 묶습니다.
- 각 그룹에 해당 데이터를 보유한 서버 및 기기 이름을 함께 표시합니다.
- 마지막 실제 데이터 수정 시각을 표시합니다. 단말 시계의 오차 가능성을 고려해 시간 정보만으로 데이터를 자동 덮어쓰지 않습니다.
- 가장 최근으로 확인되는 후보는 추천/강조 표시할 수 있지만, 데이터 그룹이 서로 다르면 최종 정본 확정 전에 사용자가 후보를 확인하고 최종 선택을 승인해야 합니다.
- 후보 스냅샷에는 최종 공유 데이터, candidate ID, 콘텐츠 해시, 스키마 버전, 원본 기기/탭 식별 정보, 마지막 수정 시각을 저장합니다.
- 같은 기기/로컬 작업 세션에서 후보를 갱신할 경우 무한히 후보를 추가하지 않고 해당 후보를 새 최종 스냅샷과 해시로 갱신합니다.

### 3.4 후보 열람과 편집
- 사용자는 각 후보를 열어 페이지, 필기, 객체, 점수, 모둠, 설정을 열람할 수 있습니다.
- 후보 편집은 서버 정본과 다른 후보에 영향을 주지 않는 격리된 임시 작업 공간에서 수행합니다.
- 후보를 편집하면 해당 후보의 최종 스냅샷, 해시, 마지막 수정 시각을 갱신합니다.
- 후보 미리보기/편집은 현재 사용 중인 정본을 덮어쓰지 않아야 합니다.
- 후보 열람/편집 중에도 서버 정본은 유지됩니다.

### 3.5 최종 정본 선택과 배포
- 사용자가 하나의 후보 그룹을 최종 선택하고 확정하면 해당 스냅샷을 새로운 서버 정본으로 승격합니다.
- 서버 정본 교체는 버전 확인과 원자적 확정으로 처리해 동시에 두 후보가 정본이 되는 일을 방지합니다.
- 교체 전에 기존 서버 정본과 후보를 복구 가능한 백업으로 보존합니다.
- 확정된 새 정본을 모든 온라인 기기에 배포합니다. 오프라인 기기는 다음 접속 시 서버 정본을 확인합니다.
- 스냅샷 복원/정본 교체는 최종 상태를 즉시 반영합니다. 과거 애니메이션, 축하 연출, 효과음, 이벤트별 대기시간은 재생하지 않습니다.
- 새 정본 확정과 배포가 성공하고 백업이 보존된 뒤 비선택 임시 후보를 삭제합니다. 확정 실패나 배포 실패 시 후보를 삭제하지 않습니다.
- 최종 정본 선택 후 다시 연결된 기기가 서버 모드였고 로컬 모드로 전환하지 않았다면, 오래된 로컬 캐시/화면 상태를 후보로 제출하지 않고 확정된 서버 정본으로 즉시 갱신합니다.
- 최종 정본 선택 후 다시 연결된 기기가 로컬 모드였다면 서버 정본과 로컬 데이터의 해시를 비교합니다. 해시가 같으면 별도 선택 없이 서버 정본에 합류하고, 해시가 다르면 해당 로컬 데이터를 새 후보로 제출해 사용자가 데이터 선택 절차를 진행합니다.

## 4. 연결 복구 시 전송 및 편집 재개

### 4.1 서버 모드였던 기기
- 연결이 끊긴 동안 편집은 차단되어 있으므로 새로운 편집 작업이 생성되지 않습니다.
- 연결 단절 전에 생성된 미확정 서버 요청은 동일 작업 ID로 재시도합니다.
- 재연결 후 서버가 이미 처리한 요청은 중복 적용하지 않습니다.
- 미확정 요청의 결과와 최신 서버 정본을 확인한 뒤 화면을 서버 상태로 갱신합니다.
- 서버 상태 확인과 대기 요청 처리가 끝난 뒤 편집을 다시 허용합니다.
- 서버 모드에서 재연결한 경우 로컬 스냅샷 후보 선택 절차를 실행하지 않습니다.

### 4.2 로컬 모드였던 기기
- 재연결 후에도 로컬 모드 편집을 유지합니다.
- 해시를 먼저 비교하고 3장의 규칙에 따라 동일 데이터는 전송을 생략하고, 새 데이터만 최종 스냅샷 후보로 제출합니다.
- 후보가 서버에 제출된 뒤에도 최종 정본이 확정되기 전까지 서버 정본을 직접 수정하지 않습니다.
- 사용자가 최종 정본을 선택하고 배포를 확정하면 새 정본으로 전환합니다.

### 4.3 중복/지연 전송 방지
- 서버 모드의 각 작업 요청에는 고유 작업 ID, 기기/탭 ID, 세션 세대 번호를 포함합니다.
- 재시도는 같은 작업 ID를 사용해 멱등적으로 처리합니다.
- 로컬 모드 전환 시 이전 서버 편집 세션을 종료하고, 이전 세션에서 늦게 도착한 요청이 새 정본이나 후보를 덮어쓰지 못하도록 서버에서 세대 번호를 검증합니다.
- 전송 결과가 불확실한 작업은 성공/실패를 추측하지 않고 서버의 작업 ID 처리 결과와 정본 버전을 확인합니다.

## 5. 이미지/PDF 파일 전송

- 이미지/PDF 바이너리는 기존 각 기기의 IndexedDB 보관 방식을 유지합니다.
- Firebase Storage 자동 업로드/다운로드/복제는 하지 않습니다.
- 기기간 실제 파일 전송은 기존 수동 P2P/WebRTC 방식을 유지합니다.
- 데이터 후보 스냅샷에는 객체 메타데이터와 파일 참조/식별자를 포함하되 바이너리는 포함하지 않습니다.
- 선택된 후보가 참조하는 파일을 현재 기기가 갖고 있지 않으면 누락 객체의 위치·크기·이름 등 메타데이터를 보존하고 수동 P2P 요청으로 확보합니다.
- 파일 보유 기기의 온라인 여부, 파일 보유 상태, 요청 실패/시간 초과, 다른 보유 기기 재시도를 표시합니다.
- 연결이 끊겨 P2P 전송이 실패하면 파일 전송을 완료로 표시하지 않고 재시도할 수 있게 합니다.
- 파일이 없는 객체도 선택·이동·이름 변경·삭제할 수 있어야 합니다.

## 6. 점수 애니메이션과 음향

### 6.1 애니메이션
- 정상 온라인 중 점수 이벤트는 모든 탭에서 즉시 수신합니다.
- 이벤트 ID와 공통 애니메이션 시작 시각을 사용해 각 탭이 같은 시간축으로 연출을 시작합니다.
- 별 이동, 진행막대, 숫자 변화 등 별개의 연출을 임의로 합치지 않습니다.
- 백그라운드 탭도 애니메이션 시간을 진행합니다. 매 프레임 렌더링을 강제하지 않고 시간 기반으로 진행률을 계산합니다.
- 탭 복귀 시 이미 끝난 연출은 재생하지 않고 진행 중인 연출의 남은 부분만 표시합니다.
- 서버 재연결로 확정된 과거 이벤트, 로컬 후보 업로드, 스냅샷 복원, 정본 교체는 복구 이벤트로 표시해 과거 애니메이션/효과음을 억제합니다.
- Windows 애니메이션 효과 설정과 웹앱 내부 애니메이션은 별개로 취급합니다.

### 6.2 음향 정책
- 기본값은 모든 탭에서 재생입니다.
- 선택 옵션은 기기마다 한 탭에서 재생, 사용자가 지정한 탭에서만 재생입니다.
- 음향 정책은 애니메이션과 독립적으로 동작합니다.
- 기기별 한 탭 선택은 탭 이름이 아닌 안정적인 기기 ID를 기준으로 합니다.
- 모든 탭에서 음향 정책을 변경할 수 있고 변경 결과는 다른 연결 탭/기기에 공유합니다.
- 브라우저 자동재생 제한은 별도 안내/사용자 제스처로 처리합니다.

## 7. 기기 및 탭 관리

### 7.1 기기 관리
- 더보기 메뉴에서 관리합니다.
- 기기 이름 변경, 연결 상태, 연결/해제를 관리합니다.
- 로컬 모드 기본 기기 이름은 "이 기기"로 표시합니다.
- 기기 ID와 표시 이름은 분리합니다.

### 7.2 탭 관리
- 화면 전송 메뉴에서 관리합니다.
- 탭 이름은 기기별로 독립적으로 부여합니다.
- 기본 이름은 탭1, 탭2, 탭3...이며 현재 열려 있는 탭 중 가장 작은 빈 번호를 재사용합니다.
- 같은 기기의 탭1과 다른 기기의 탭1은 서로 다른 탭입니다.
- 페이지 번호/페이지 이름은 탭 표시 이름에 넣지 않습니다.
- 사용자는 탭 이름을 직접 변경할 수 있습니다.
- 새로고침은 같은 탭 ID로 복원하여 이름을 유지합니다. 탭을 완전히 닫고 새로 열면 새 실행으로 보고 빈 번호를 재사용합니다.
- 기기 이름과 탭 이름을 함께 표시합니다(예: "교실 PC · 탭1").
- 탭 상태는 활성, 대기 중, 오프라인을 구분합니다. 백그라운드 탭은 대기 중이며 오프라인이 아닙니다.
- 브라우저 종료/탭 종료는 연결 목록에서 제거합니다. 비정상 종료는 제한된 만료 시간 이후 정리합니다. 백그라운드 타이머 제한만으로 오프라인 판정하지 않습니다.

## 8. 화면 상태 일회성 전송과 점수판 툴바
- 상시 체크/지속 구독 방식이 아니라 전송 버튼을 눌러 대상 탭을 선택합니다.
- 체크박스로 한 번의 전송 대상 탭을 고릅니다.
- 현재 화면 상태를 일회성으로 보냅니다.
- 점수판 버튼의 명칭은 항상 "점수판"이며 활성 상태만 시각적으로 표시합니다.

## 9. 객체 관리 및 기존 기능 보존
- 원본 파일이 없어도 이미지 객체를 선택·이동·삭제할 수 있습니다.
- 우클릭 메뉴에서 객체 이름을 변경할 수 있습니다.
- 다중 선택 일괄 이름 변경은 (1), (2), (3) 형식으로 부여합니다.
- 파일 관리 목록에는 객체 종류와 이름을 표시합니다.
- 우클릭 메뉴 상단에 현재 객체 이름을 표시합니다.
- 6.1에 있는 필기, 텍스트, 도형, 페이지, 점수판, 저장/불러오기, PDF, 클립보드, 확대/축소, 배경, 툴바 기능을 보존합니다.

## 10. 데이터 호환성 및 안전
- 기존 6.1 Firebase 공유 칠판의 데이터와 기기 연결 정보를 확인하고 승계합니다.
- 서버 스키마 변경은 버전 필드와 마이그레이션 경로를 마련한 뒤 적용합니다.
- 로컬 DB는 경로 기반 키를 사용해 6.1과 분리합니다.
- 정본 교체 전 서버 정본과 후보 백업을 생성하고 복구 절차를 제공합니다.
- 동시 객체 제어권 이전, 동시 점수 증감, 전역 되돌리기, 객체/페이지 삭제 중 편집, 재시도 중복, 로컬 전환 중 미확정 전송, 다중 로컬 후보, 부분 배포를 검증합니다.
- 기존 6.1에서 사용하는 Firestore 규칙과 신규 후보/제어권 저장 권한을 별도 검토합니다.
- Firestore 문서 크기 제한을 고려해 스냅샷 메타데이터와 청크 분할 구조를 설계합니다. Firebase Storage로 이미지/PDF를 자동 보관하지 않습니다.

## 11. 검증 계획

### 11.1 온라인 충돌
- 서로 다른 객체를 두 기기에서 동시에 편집해 두 작업이 모두 유지되는지 확인.
- 같은 객체를 다른 기기에서 클릭했을 때 제어권이 이전되고 이전 기기의 선택/핸들이 해제되는지 확인.
- 다중 선택 중 일부 객체의 제어권만 빼앗겼을 때 해당 객체만 해제되는지 확인.
- 제어권을 잃은 기기의 늦은 변경 요청이 거부되는지 확인.
- 드래그/텍스트 편집 중 제어권 이전 시 확정된 변경과 미확정 입력이 명세대로 처리되는지 확인.
- 객체 삭제 및 페이지 삭제가 모든 온라인 기기에서 즉시 반영되고, 늦은 편집 이벤트로 부활하지 않는지 확인.
- 점수 증감이 서버 확정 순서로 누적되고 재시도 중 중복 반영되지 않는지 확인.
- 점수 직접 수정과 동시에 발생한 증감은 직접 수정이 먼저 확정되고 새 기준값에 이어 적용되는지 확인.
- 다른 기기가 텍스트 입력 중 제어권을 요청하면 기존 입력이 강제 완료·서버 확정된 뒤 제어권이 이전되고, 새 기기에서 최신 텍스트가 보이는지 확인.
- 한글 IME 조합 중 제어권 이전 요청이 발생해도 조합 중인 글자가 누락되지 않고 확정되는지 확인.
- 객체를 선택한 채 정상 연결을 유지하면 제어권이 시간 경과만으로 만료되지 않고, 선택 해제/페이지 이동/탭 종료 시 해제되는지 확인.
- 선택 중인 탭이 비정상 종료되면 임대 만료 후 제어권이 회수되는지 확인.
- 여러 기기에서 되돌리기/다시 실행을 수행해 공유 작업 순서가 유지되는지 확인.
- 같은 전역 설정을 동시에 변경하면 마지막 서버 확정 값이 적용되는지 확인.

### 11.2 연결 단절과 로컬 전환
- 서버 모드 연결 단절 시 모든 편집이 차단되고 안내가 표시되는지 확인.
- 서버 모드에서 기존 미확정 요청만 재시도되고 새로운 편집 작업은 생성되지 않는지 확인.
- 서버 모드였던 기기는 재연결 시 오래된 로컬 상태를 후보로 제출하지 않고 서버 정본으로 갱신되는지 확인.
- 로컬 모드였던 기기는 재연결 후 해시가 같으면 서버 정본에 합류하고, 다르면 후보 선택 절차를 진행하는지 확인.
- 서버 연결 복구 시 미확정 요청을 중복 없이 확정하고 최신 서버 상태를 받은 뒤 편집이 재개되는지 확인.
- 로컬 모드 전환 시 미확정 서버 전송이 취소되고 독립 로컬 작업 공간이 생성되는지 확인.
- 여러 기기가 각각 로컬 모드로 작업해도 서로 간섭하지 않는지 확인.
- 로컬 모드에서 재연결해도 자동으로 서버 모드로 바뀌지 않는지 확인.

### 11.3 해시·후보·정본 선택
- 서버와 같은 해시는 스냅샷 업로드 없이 연결되는지 확인.
- 기존 후보와 같은 해시는 중복 업로드 없이 같은 그룹에 합류하는지 확인.
- 새로운 해시만 최종 스냅샷으로 제출되는지 확인.
- 여러 기기의 동일 데이터가 하나의 선택지로 묶이고 보유 기기 이름이 모두 표시되는지 확인.
- 서로 다른 후보를 열람·편집해도 다른 후보와 서버 정본이 변경되지 않는지 확인.
- 최종 정본 선택, 백업, 온라인 기기 배포, 비선택 후보 정리가 안전한 순서로 수행되는지 확인.
- 배포 실패 시 후보와 백업이 보존되는지 확인.
- 재연결/정본 교체 때 과거 애니메이션과 효과음이 재생되지 않는지 확인.

### 11.4 기존 기능 및 실기기
- 이미지/PDF 수동 P2P 전송, 누락 객체 관리, 파일 보유 기기 표시.
- 점수 애니메이션 동시 재생, 백그라운드 탭 진행, 탭 복귀 시 과거 연출 생략.
- 음향 세 가지 정책.
- 기기/탭 이름, 탭 번호 재사용, 활성/대기/오프라인 표시.
- 화면 상태 일회성 전송과 점수판 버튼.
- Windows Edge/Chrome, Android 삼성 브라우저, 태블릿, 전자칠판 실기기 검증.

## 12. 보류 및 구현 전 확정 항목

### 12.1 보류
- 별도 PWA/실행 주소 구성.
- Windows 창 위치 자동 배치 및 다중 자동 시작.
- Firebase Storage 서버 파일 보관.
- 사용자 지시 전에는 위 항목을 구현하지 않습니다.

### 12.2 구현 전에 추가 확정할 항목
1. 객체 제어권 임대 시간, 갱신 간격, 비정상 종료 후 회수 시간의 구체적인 수치는 구현 전 성능/연결 테스트로 정합니다. 정상적으로 선택 중인 객체의 제어권은 유지하며, 임대 만료는 비정상 종료 등 갱신 중단 상황의 회수에만 사용합니다.
2. Firestore 후보 스냅샷 청크 크기, 업로드 재개, 후보 만료 정책.
3. 서버 정본/후보의 마지막 수정 시각 신뢰도와 최신 후보 추천 기준.

## 1. 프로젝트의 목적과 사용 환경

이 앱은 교실 PC·교사용 태블릿·전자칠판에서 하나의 칠판과 학급/모둠 점수판을 사용하는 **독립 실행형 웹앱**입니다.

- 전자칠판: Fabric.js 기반 필기/형광펜/텍스트/도형/그룹/이미지·PDF/페이지/배경 등.
- 점수판: 학급 점수, 모둠 점수, 모둠→학급 환산, 별 이동과 진행막대, 목표·달성 연출, 음향.
- 화면 구성: 전자칠판 전체 화면을 유지한 상태로 우측 점수판 패널을 켜고 끔. 하단 툴바는 공통. 사용자 선호는 **한눈에 빠르게 조작**, 상단 상태바·불필요한 모드/UI 추가는 지양.
- 다중 기기: Firebase Authentication(익명 로그인) + Firestore로 칠판/점수/기기 메타데이터 공유. 이미지·PDF 바이너리는 기기별 IndexedDB에 보관하며 **WebRTC 수동 전송**.
- 실행 환경: Windows Edge 브라우저/PWA, 일반 PC 브라우저, Android 삼성 인터넷, 태블릿, 전자칠판. 같은 기기의 복수 탭과 서로 다른 기기를 별개로 다룸.
- Firebase 비용 최소화 원칙: Firebase Storage 자동 업로드, 자동 복제, 중계 서버 운영을 추가하지 않음.

## 2. 개발 연혁 — 왜 6.2까지 왔는가

### 2.1 원본 → 6.0 (`/만능칠판-test/`)
- 기존 전자칠판(과거 `만능칠판2` 계열)과 점수판(`학급온도계-6` 계열)을 하나의 독립 실행형 앱으로 통합했습니다.
- 원본에 런타임 의존하지 않도록 점수판 파일을 `score/`에 포함, 칠판 위에 우측 점수판 패널을 표시했습니다.
- 패널 ON/OFF, 기본 70:30, 드래그 분할, 카드 자동/고정 열 배치, 금색 진행막대·별 이동, 공통 툴바, 페이지/객체 조작을 정리했습니다.
- Firebase 공유 칠판의 연산 로그, 기기 등록, 웹RTC 파일 전송을 도입했습니다.
- 이후 실제 사용에서 **오랫동안 접속하지 않은 노트북의 점수판이 서버의 과거 이벤트를 하나씩 애니메이션으로 재생하는 현상**, 다중 기기 간 애니메이션 시차, 음향 중복, 백그라운드 탭 문제가 제기되었습니다.

### 2.2 6.1 (`/만능칠판6.1/`)
6.0의 최종 대체를 목표로 개선한 다음 세대의 기능 기준선입니다.

- **화면 전송:** 대상 탭을 체크하고 현 시점 화면 상태를 **한 번만** 전송. 장기간 상시 추종 기능과 구분.
- **점수판 툴바:** 버튼 이름을 항상 `점수판`으로 유지, 활성 여부만 시각 표시.
- **점수 연출:** 점수 이벤트 미리보기 전달 순서 개선, 확정 이벤트 수신 시 중복 연출 방지, 일반 음량 재생 경로 단순화.
- **객체/파일:** 원본 파일이 없어도 이미지/PDF 객체 선택·이동·삭제 가능; 우클릭 이름 변경; 다중 이름 `(1), (2)…` 부여; 파일 관리에 객체 종류·이름 표시.
- **다중 기기/탭:** 표시 이름, 음향 정책(모든 탭/기기별/선택 탭), 화면 전송 목록 관련 모듈 도입.
- **수정과 검증은 구분:** 코드 반영 기록은 있지만 실제 Windows/Android/Firebase 전체 조합의 기능 검증을 완료했다고 간주하지 않습니다.

### 2.3 6.2 생성 (`/만능칠판6.2/`)
- 2026-11-18에 6.1 소스 약 90개 파일을 복사하여 별도 폴더를 생성했습니다.
- 6.0/6.1과 병행 운용하기 위한 새로운 제품이 아니라 **장차 6.1을 대체할 완성판**을 목표로 합니다.
- 논의 과정에서 기존의 **오프라인 연산 누적·서버 재생·조작별 충돌 해결**이 복잡하다고 판단해 다음의 단순한 운영 원칙을 합의했습니다:
  1. **온라인:** 서버가 작업 순서를 확정하고, 같은 객체는 마지막 클릭 기기가 제어권을 가져감.
  2. **서버 연결 끊김:** 서버 모드에서는 편집 불가. 연결 전 생성된 전송은 재시도.
  3. **명시적 로컬 전환:** 사용자 선택으로만 독립 로컬 편집 가능.
  4. **로컬 재연결:** 과거 연산을 서버에 순차 재생하지 않고 **최종 상태 스냅샷만 비교/제출**.
  5. **데이터 최종 선택:** 동일 해시는 묶고, 서로 다른 후보는 열람·편집 후 하나의 정본으로 선택.
- 현재는 이 설계를 문서화하고 **1차 객체 제어권 코드 연결**만 마친 단계입니다.

## 3. 6.2 최종 합의 — 온라인 충돌 규칙

### 3.1 객체 제어권
- 서로 다른 객체: 여러 기기가 각각 동시에 편집 가능.
- 같은 객체: **나중에 클릭한 기기/탭이 제어권 획득**. 이전 소유자의 해당 객체 선택·편집 핸들 해제.
- 여러 객체 선택 중 일부만 탈취당하면 그 객체만 선택에서 제외, 나머지 유지.
- **제어권은 선택 중 계속 유지**하며 주기적으로 갱신. 선택 해제/페이지 이동/편집 종료 시 반환. 비정상 종료 등 갱신이 끊긴 경우에만 만료 회수.
- 기존 기기가 **텍스트 입력 중**이면 **입력 취소 금지**. `입력 강제 완료 → 최종 텍스트 서버 확정 → 기존 편집 종료 → 새 소유자 편집 시작`. 특히 한글 IME 조합 중 입력 누락 금지.
- 같은 객체의 위치/크기/색상을 속성별로 복잡하게 병합하지 않고 **독점 제어권과 확정 순서**로 해결.
- 오래된 제어권 토큰이 붙은 늦은 변경 요청은 서버에서 거부해야 함.

### 3.2 객체·페이지 삭제
- 다른 기기에서 삭제하면 편집 중이던 기기도 **삭제가 전파되는 즉시 대상을 제거**합니다. 삭제를 위해 사전 페이지 잠금을 걸거나 다른 기기 작업을 기다리지 않습니다.
- 삭제된 객체/페이지의 과거 지연 이벤트가 대상을 부활시키지 않도록 삭제 버전과 요청 검증이 필요합니다.
- 오프라인에서 명시적으로 로컬 모드로 바꾼 기기에는 페이지가 남을 수 있으며, 나중에 스냅샷 후보를 선택합니다.

### 3.3 점수·설정·되돌리기
- 점수 `+/-`는 작업 완료/서버 확정 순서대로 모두 누적합니다. 중복 전송은 작업 ID로 방지.
- 점수 **절대값 직접 수정 우선**: 같은 점수에 동시에 입력되면 직접 수정으로 기준값을 먼저 정하고 증감은 새 기준값에 적용. 예: 10점에서 20점 직접 수정과 +3이 겹치면 23점.
- 점수 직접 수정은 되돌리기 대상으로 취급하지 않습니다.
- 되돌리기는 각 기기 개인 이력 대신 **서버에서 확정된 전체 작업 순서**를 따라 가장 최근의 되돌릴 수 있는 작업부터 취소. 다른 기기가 한 작업도 대상이 될 수 있음.
- 페이지 순서·배경·격자 등 전역 상태는 서버 순서/같은 설정 항목의 마지막 확정값 우선.
- 파일 바이너리 전송과 객체 메타데이터 편집은 서로 분리.

## 4. 6.2 최종 합의 — 연결 끊김/로컬 모드

| 상황 | 편집 | 전송/판정 |
|---|---|---|
| 서버 모드 + 온라인 | 가능 | 서버에 즉시 작업 전송 |
| 서버 모드 + 연결 끊김 | **불가** | 단절 전 생성한 요청만 동일 작업 ID로 재시도 |
| 사용자가 **로컬 모드로 전환** | 가능 | 서버 편집 대기 취소, 현재 화면/점수 기반 독립 작업 |
| 로컬 모드 + 인터넷 복구 | 계속 가능 | 자동 서버 덮어쓰기 금지, **해시부터 비교** |

연결이 끊겼을 때 안내 문구: **“오프라인에서는 편집할 수 없습니다. 잠시 후 다시 시도해주세요.”** 사용자가 로컬 모드로 전환한 경우에만 계속 조작할 수 있습니다. 자동 로컬 전환은 하지 않습니다.

**로컬 재연결 절차**
1. 로컬 공유 데이터의 **정규화된 SHA-256** 해시를 계산. 기기 이름/탭 이름/온라인 상태 등 비본질적 값은 제외.
2. 서버 정본과 해시가 같으면 업로드 생략, 서버 정본과 합류.
3. 기존 임시 후보와 같으면 스냅샷 중복 업로드 없이 해당 그룹에 기기 등록.
4. 새로운 해시일 때만 **최종 스냅샷**을 임시 제출. **과거 개별 편집/증감/되돌리기 연산은 재전송하지 않음**.
5. 서버·기기 후보를 해시별로 묶고, 보유 기기 이름 및 마지막 실제 수정 시각을 표시.
6. 사용자가 각 후보를 **열람하고 필요하면 독립적으로 편집**한 뒤 하나를 최종 정본으로 확정.
7. 확정 전 백업, 정본의 원자적 교체 및 전체 온라인 기기 배포, 성공 확인 후 비선택 임시 후보 삭제. 실패했을 때 후보/백업 보존.
8. 오래된 기기가 귀환해도 **서버 모드였으면 서버 정본으로 동기화**, **로컬 모드였으면 해시 비교 후 다른 내용일 때 후보 선택**.

이미지/PDF 바이너리는 이 스냅샷에 담지 않습니다. 파일의 참조/식별자/객체 속성만 공유하고 실제 파일은 수동 P2P로 요청합니다. 복원 때 과거 점수 애니메이션/효과음을 재생하지 않습니다.

## 5. 점수 연출·음향·탭 UX 확정 방향

- 점수 이벤트 ID와 **공통 시작 시각** 기준으로 모든 탭에서 가능한 한 같은 시점에 연출. 펜/별/진행막대/점수 숫자를 무리하게 한 효과로 합치지 않음.
- 백그라운드 탭은 불필요한 매 프레임 렌더링 대신 **경과 시간 기반 진행**. 다시 활성화하면 끝난 애니메이션을 재실행하지 않고 현재 상태 또는 남은 부분만 표시.
- 서버 초기 로드·장기간 오프라인 후 재연결·정본 교체는 중간 과거 상태를 단계별로 보여주지 않고 **최종 상태 즉시 반영**.
- 소리 정책: (1) 모든 탭 재생(기본), (2) 기기마다 한 탭 재생, (3) 사용자가 재생할 탭 지정. 음향과 영상 연출은 별개.
- 탭 이름: 같은 기기에서는 빈 번호를 재사용하는 `탭1, 탭2…`, 다른 기기는 각각 독립 카운트. 자동 쪽번호/페이지 이름 반영 제거. 표시 이름과 기기/탭 ID는 분리.
- 기기 관리: **더보기**. 탭 이름 관리/화면 상태 일회성 전송: **화면 전송**. 로컬 기본 기기 이름은 **이 기기**.
- 탭 백그라운드 대기와 서버 연결 오프라인은 다른 상태이며, 비활성 탭을 단순 오프라인으로 판정하지 않음.
- 별도 PWA 실행 주소/매니페스트, 자동 모니터 배치, Windows 자동 실행, Firebase Storage 도입은 **보류**.

## 6. 실제 구현 상태: '코드에 존재'와 '요구 충족'을 혼동하지 말 것

| 범위 | 2026-11-18 소스 기준 | 유의점 |
|---|---|---|
| 6.1 기반의 칠판·점수판·저장·파일·툴바 | **기존 코드 승계** | 6.2 실기기 회귀 검증 없음 |
| 객체 잠금 모델, 잠금 요청·갱신·반납 | **코드 존재** | `js/cloud.js`, `js/object-control.js` |
| 캔버스 선택과 잠금 연동 | **1차 연결** | `script.js`. 다중 선택/그룹/동시 클릭 테스트 필요 |
| 텍스트 강제 완료 후 잠금 이전 | **1차 연결** | 한글 IME·확정 시점·서버 승인 순서 실기기 미검증 |
| 서버 모드 오프라인 시 캔버스 차단 | **1차 연결** | 점수판, 모든 명령 경로의 일관된 차단 및 안내 UX 재검증 필요 |
| `objectLocks` Firestore 규칙 | **저장소 파일 수정** | **실제 Firebase 콘솔에 배포/적용됐다는 증거 없음** |
| 서버 모드 끊김 → 전용 로컬 전환 UX | **미구현** | 기존 '연결 해제' 기능과 새 요구는 같지 않음 |
| SHA-256, 후보 스냅샷, 동일 해시 그룹화 | **미구현** | 후보 데이터 저장소/업로드/스키마 설계 필요 |
| 후보 열람·편집·최종 정본 승격·배포·정리 | **미구현** | 운영 데이터 백업 필수 |
| 직접 수정 우선 서버 확정 | **미구현** | `js/score-conflicts.js`의 기존 서버 순서 처리와 비교 필요 |
| 전체 공유 되돌리기 | **부분/별도 검증 필요** | 점수/페이지 단위 기존 이력과 요구 차이 검사 |
| 모든 탭 공통 시간축의 배경 애니메이션 | **요구 수준 검증/보완 필요** | 현 점수판 코드는 `!document.hidden` 조건 사용 |
| 기본 탭 이름 `탭1` 및 로컬 `이 기기` | **검증/보완 필요** | `js/view-tabs.js`에 `row.page+'쪽'`/`'이 브라우저'` 폴백 남음 |
| 자동 테스트·브라우저·Firebase 실기기 | **6.2 통과 미확인** | 단위 테스트가 추가된 것과 실제 실행·통과는 다름 |

**중요한 코드/설계 간 차이**
- `js/cloud.js`의 기존 `pending`/`pull`/`push` 구조는 **연산 로그 동기화 방식**으로 남아 있습니다. 로컬 모드 스냅샷 선택 설계를 구현했다고 오인하면 안 됩니다.
- `js/cloud-model.js`는 페이지/점수 연산을 서버 확정 순서대로 적용합니다. 삭제된 페이지의 늦은 편집 무시는 기본 제공되지만 잠금 토큰/삭제 세대/전체 재접속 경로까지 충분한지 검증이 필요합니다.
- `score/script.js`는 숨겨진 탭의 효과 재생에 조건을 두고 있어 '같은 시작 시각, 복귀 시 남은 부분' 요구를 완전히 충족했다고 단정할 수 없습니다.
- `BROWSER-CHECKLIST.md`는 6.0 시절의 동일 브라우저 충돌 복구 동작을 요구하는 항목이 있습니다. 6.2의 온라인 객체 제어권/오프라인 후보 설계가 우선이며 체크리스트도 갱신해야 합니다.
- **Firestore 규칙 교체와 Firebase 데이터 마이그레이션은 GitHub 수정만으로 자동 배포되지 않습니다.**

## 7. 코드 구조와 필수 파일

| 파일 | 역할 |

| `js/cloud-model.js` | 페이지 추가/수정/삭제, undo/redo, 서버 연산 적용 |
| `js/object-control.js` | 객체 잠금 문서 ID, 제어권 토큰, 임대 갱신 판정 |

| `score/script.js`, `score/` | 점수판 UI, 진행막대·별 연출·음향 |

## 8. 다음 작업자 권장 실행 순서

1. **현황/보안 확인:** 최신 `main` 확인 → 기존 6.2와 6.1 비교 → Firestore 규칙/인증 구조 읽기 → 운영 Firebase 데이터 백업 계획 수립.
2. **1차 구현 결함 수정:** 객체 잠금의 획득/탈취/선택 해제/그룹 편집/강제 텍스트 완료/오프라인 편집 차단을 안전하게 완성. 특히 누락 편집 저장·대기열 경합·한글 IME 확인.
3. **서버 모드 연결 단절 처리 통일:** 모든 편집 경로(점수판 포함) 차단, 기존 미확정 전송만 멱등 재시도, 연결 복구 시 서버 정본 확인 후 해제.
4. **명시적 로컬 전환:** 서버 작업 세션 종료, 미확정 요청 취소·불확실한 서버 반영 여부 확인, 화면/점수/설정 로컬 작업 공간 분리. 다중 로컬 기기 허용.
5. **해시 우선 후보 처리:** 정규 직렬화 → SHA-256 → 중복 없는 후보 등록 → 후보별 격리 열람/편집 → 정본 선택/백업/원자적 승격/배포/정리. 이미지/PDF 바이너리 제외.
6. **점수 직접 수정 우선 및 공유 undo:** 서버 확정 순서/작업 ID/되돌리기 대상 정책 구현. 필요 시 기존 점수 필드 충돌 UI 정리하되 기존 기능 훼손 금지.
7. **연출/탭/파일 회귀:** 배경 탭 시간축, 재접속 과거 애니메이션 방지, 음향 정책, 탭1 이름·기기 ID, 화면 상태 일회성 전송, P2P 수동 파일 복구.
8. **테스트:** `npm test` + Windows Edge/Chrome(복수 탭), Android 삼성 인터넷, 태블릿/전자칠판, Firebase 두 기기 이상 + 장기 오프라인/정본 교체 재현. **브라우저 실기기 검증 결과 없이 6.2 정식 전환 금지.**

우선 확인해야 하는 대표 시나리오:
- PC 텍스트 입력 중 태블릿이 같은 객체 선택 → PC 입력 강제 완료/서버 확정 → 태블릿 최신 텍스트로 편집.
- PC가 3쪽 삭제, 태블릿이 같은 페이지 편집 → 온라인 태블릿에서는 즉시 사라짐. 태블릿이 **로컬 모드**였다면 3쪽이 남고 재연결 시 다른 후보로 제출.
- 서버 10점에서 PC +3, 태블릿 +2 → 15점, 중복 재시도 없음. 직접 수정 20과 +3이 겹치면 23점.
- 서버 모드에서 네트워크 끊김 → 필기/점수 입력 금지 → 재연결 시 과거 연출 없음. 로컬 전환 선택 후에는 독립 편집 허용.
- A/B/C 로컬 기기 중 일부의 해시가 서버 또는 다른 후보와 동일 → 실제 스냅샷 중복 업로드하지 않음.
- 오래 접속하지 않은 새 기기 → 최신 화면/점수를 **최종 상태로 한번에** 수신, 과거 애니메이션을 모두 재생하지 않음.

## 9. 구현·검증·배포 작업 원칙

- **설계 명세와 실제 코드는 별개**입니다. 구현되지 않은 항목을 완료로 보고하지 말 것.

- 사용자에게 개발을 시작/수정하라고 명시적으로 지시받은 범위에서 코드 변경할 것. 보류 항목은 임의로 구현하지 말 것.
- 문서 작성, 코드 작성, 자동 테스트, 실제 브라우저 검증, Firebase 규칙 배포를 각각 **서로 다른 완료 단계**로 보고할 것.
- GitHub 반영 시 변경 파일과 커밋 SHA, 테스트 결과, 남은 미완료 항목을 명확히 보고할 것.
- 외부 서비스의 비밀정보·실제 Firebase 인증 정보·초대 키를 이 문서에 기록하지 말 것.

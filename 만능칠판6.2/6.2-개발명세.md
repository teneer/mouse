# 만능칠판 6.2 개발 명세

작성 기준: 2026-11-18
기준 소스: 만능칠판 6.1, main 커밋 `81a2414de8d74288e8ece156faecf2f28efa9413`

## 0. 범위와 보호 원칙

- 6.2 개발 위치는 `/만능칠판6.2/`입니다.
- 6.1 및 만능칠판-test 원본은 수정하지 않습니다.
- 6.1을 기능 기준선으로 삼고, 기존 필기·페이지·점수판·도형·이미지/PDF·화면전송·동기화·객체관리 기능을 보존합니다.
- 6.2의 목적은 6.1을 대체할 차기 버전을 만드는 것입니다. 실제 전환은 자동 테스트와 브라우저/Firebase 실기기 검증 후에만 판단합니다.
- 기존 Firebase 학급 데이터 승계를 기본으로 합니다. 같은 Firebase 프로젝트와 기존 공유 칠판 ID를 사용하되, 서버 데이터 구조 변경은 호환성 계획과 백업을 먼저 마련합니다.
- 6.2의 경로 기반 IndexedDB/localStorage 키는 6.1과 분리합니다. 서버 데이터는 동일 Firebase 프로젝트/board ID를 사용할 경우 공유될 수 있으므로 서버 쓰기 경로는 특히 주의합니다.

## 1. 서버 모드와 로컬 모드

### 1.1 기본값: 서버 모드
- 정상 접속 시 서버 모드로 시작합니다.
- 서버 모드에서는 Firebase의 공유 칠판 상태가 정본입니다.
- 여러 온라인 기기와 탭은 실시간으로 서버 상태를 공유합니다.
- 서버 연결이 끊기면 자동으로 조용히 로컬 편집을 계속하지 않습니다.

### 1.2 연결 단절 시
- 연결이 끊기면 "서버 연결이 끊겼습니다. 현재 상태 그대로 로컬 모드로 전환하시겠습니까?"라고 묻습니다.
- 사용자가 전환을 선택하면 서버에서 마지막으로 확인한 현재 화면/데이터를 로컬 저장소에 복사하고 이 기기만 독립적으로 작업합니다.
- 사용자가 전환하지 않으면 서버 모드의 읽기 전용/재연결 대기 상태를 유지합니다. 재연결 후 서버 최신 상태를 다시 확인합니다.
- 여러 기기가 각각 독립적으로 로컬 모드에 진입하는 것을 허용합니다. 한 기기만 오프라인 작업을 담당하도록 제한하지 않습니다.
- 로컬 모드의 점수 조정, 되돌리기, 필기, 페이지 관리 등 기존 기능은 로컬 범위 안에서 정상 작동합니다.

## 2. 오프라인 복귀와 데이터 후보

### 2.1 최종 스냅샷 제출
- 로컬 모드에서 온라인으로 돌아오면 해당 기기의 최종 데이터 상태를 서버의 임시 후보로 제출합니다.
- 점수 변경 이벤트, 되돌리기 이벤트, 편집 이벤트의 전체 로그를 누적 제출하지 않습니다.
- 임시 후보에는 최종 데이터 스냅샷, 기기 식별/표시 정보, 마지막 실제 데이터 수정 시각, 스키마 버전, 콘텐츠 지문을 저장합니다.
- 로컬 작업 중 Undo/Redo는 해당 기기의 로컬 편집 기능으로 유지할 수 있지만, 최종 후보 스냅샷에는 과거 작업 이력을 승계하지 않습니다. 새 정본 확정 후 공유 Undo 이력은 새 기준으로 시작합니다.
- 스냅샷 업로드는 멱등적으로 설계합니다. 같은 후보를 재전송해도 중복 후보가 쌓이지 않아야 합니다.

### 2.2 데이터 지문과 그룹화
- 정규화된 공유 데이터에 SHA-256 콘텐츠 지문을 계산합니다.
- 지문에는 공유 페이지/객체/점수/모둠/설정 등 정본 상태를 구성하는 데이터를 포함합니다.
- 기기 이름, 탭 이름, 온라인 상태, 커서/뷰포트 등 일시적 표시 정보는 데이터 지문에서 제외합니다.
- 동일한 지문을 가진 서버/기기 후보는 하나의 선택지로 묶습니다.
- 각 그룹에는 해당 데이터를 가진 서버 및 기기 이름을 모두 표시합니다.
- 마지막 실제 데이터 수정 시각을 표시합니다. 단말 시계가 틀릴 수 있으므로 기기 시각만으로 정본을 자동 결정하지 않습니다.
- 최신 후보는 참고 배지로 표시할 수 있지만, 최종 데이터는 사용자가 직접 선택합니다.
- 최초 도입 시 기존 데이터에는 지문이 없으므로 한 번의 초기 정규화/지문 계산이 필요합니다.
- 대용량 스냅샷은 Firestore 문서 크기 제한을 고려해 메타데이터와 청크로 분할하는 방식을 검토합니다. Firebase Storage로 이미지/PDF를 자동 보관하는 것은 범위 밖입니다.

### 2.3 후보 열람과 편집
- 사용자는 각 후보를 열어 페이지, 필기, 점수, 모둠, 설정을 확인할 수 있습니다.
- 후보 편집은 격리된 임시 작업 공간에서 수행합니다. 서버 정본이나 다른 후보를 즉시 변경하지 않습니다.
- 후보를 편집하면 콘텐츠 지문과 마지막 수정 시각을 갱신합니다.
- 후보 미리보기/편집은 현재 사용 중인 정본을 덮어쓰지 않아야 합니다.
- 후보를 편집한 뒤에도 사용자가 최종 선택을 확정해야 합니다.

### 2.4 최종 선택과 배포
- 사용자가 하나의 데이터 그룹을 선택하면 해당 스냅샷을 새로운 서버 정본으로 승격합니다.
- 서버 정본 교체는 버전 확인/원자적 확정으로 처리하여 동시 선택이나 중복 확정을 방지합니다.
- 교체 전에 기존 서버 정본과 후보를 복구 가능한 백업으로 보존합니다.
- 확정 후 온라인 기기는 새 정본을 즉시 받으며, 오프라인 기기는 다음 접속 시 새 정본을 받습니다.
- 복구/정본 교체는 최종 상태를 즉시 반영합니다. 과거 점수 애니메이션, 축하 연출, 효과음을 재생하지 않고 인위적인 대기시간을 두지 않습니다.
- 모든 온라인 기기의 새 정본 적용이 확인되고 백업이 안전하게 보존된 뒤 비선택 임시 후보를 삭제합니다.
- 선택된 정본을 서버에 확정하기 전에는 어떤 후보도 삭제하지 않습니다.

## 3. 이미지/PDF 파일

- 이미지/PDF 바이너리는 기존 각 기기의 IndexedDB 보관 방식을 유지합니다.
- Firebase Storage 자동 업로드/다운로드/복제는 하지 않습니다.
- 기기간 실제 파일 전송은 기존 수동 P2P/WebRTC 방식을 유지합니다.
- 데이터 후보의 스냅샷에는 객체 메타데이터와 파일 참조/식별자를 포함할 수 있지만 바이너리는 포함하지 않습니다.
- 선택된 후보가 참조하는 파일을 현재 기기가 갖고 있지 않으면 누락 객체 자리/메타데이터를 보존하고 수동 P2P 요청으로 확보합니다.
- 보유 기기 온라인 여부, 파일 보유 상태, 요청 실패/시간 초과, 다른 보유 기기 재시도를 명확히 표시합니다.
- 파일이 없는 객체도 선택·이동·이름 변경·삭제할 수 있어야 합니다.

## 4. 점수 애니메이션과 음향

### 4.1 애니메이션
- 정상 온라인 중 점수 이벤트는 모든 탭에서 즉시 수신합니다.
- 이벤트 ID와 공통 애니메이션 시작 시각을 사용해 각 탭이 같은 시간축으로 연출을 시작합니다.
- 별 이동, 진행막대, 숫자 변화 등 별개의 연출을 임의로 합치지 않습니다.
- 백그라운드 탭도 애니메이션 시간을 진행합니다. 매 프레임 렌더링을 강제하지 않고 시간 기반으로 진행률을 계산합니다.
- 탭 복귀 시 이미 끝난 연출은 재생하지 않고 진행 중인 연출의 남은 부분만 표시합니다.
- 스냅샷 복원, 로컬 후보 업로드, 정본 교체, 재연결 복구는 모두 복구 이벤트로 표시해 과거 애니메이션/효과음을 억제합니다.
- Windows 애니메이션 효과 설정과 웹앱 내부 애니메이션은 별개로 취급합니다.

### 4.2 음향 정책
- 기본값: 모든 탭에서 재생.
- 선택 옵션: 기기마다 한 탭에서 재생.
- 선택 옵션: 사용자가 지정한 탭에서만 재생.
- 음향 정책은 애니메이션과 독립적으로 동작합니다.
- 기기별 한 탭 선택은 탭 이름이 아닌 안정적인 기기 ID를 기준으로 합니다.
- 모든 탭에서 음향 정책을 변경할 수 있고 변경 결과는 다른 연결 탭/기기에 공유합니다.
- 브라우저 자동재생 제한은 별도 안내/사용자 제스처로 처리합니다.

## 5. 기기 및 탭 관리

### 5.1 기기 관리
- 더 보기 메뉴에서 관리합니다.
- 기기 이름 변경, 연결 상태, 연결/해제를 관리합니다.
- 로컬 모드 기본 기기 이름은 "이 기기"로 표시합니다.
- 기기 ID와 표시 이름은 분리합니다.

### 5.2 탭 관리
- 화면 전송 메뉴에서 관리합니다.
- 탭 이름은 기기별로 독립적으로 부여합니다.
- 기본 이름은 탭1, 탭2, 탭3...이며 현재 열려 있는 탭 중 가장 작은 빈 번호를 재사용합니다.
- 같은 기기의 탭1과 다른 기기의 탭1은 서로 다른 탭입니다.
- 페이지 번호/페이지 이름은 탭 표시 이름에 넣지 않습니다.
- 사용자는 탭 이름을 직접 변경할 수 있습니다.
- 새로고침은 같은 탭 ID로 복원하여 이름을 유지합니다. 탭을 완전히 닫고 새로 열면 새 실행으로 보고 빈 번호를 재사용합니다.
- 기기 이름과 탭 이름을 함께 표시합니다(예: "교실 PC · 탭1").
- 탭 상태는 활성, 대기 중, 오프라인을 구분합니다. 백그라운드 탭은 대기 중이며 오프라인이 아닙니다.
- 브라우저 종료/탭 종료는 연결 목록에서 제거합니다. 비정상 종료는 제한된 만료 시간 이후 정리합니다. 백그라운드 타이머 제한만으로 오프라인 판정하지 않습니다.

## 6. 화면 상태 일회성 전송
- 상시 체크/지속 구독 방식이 아니라 전송 버튼을 눌러 대상 탭을 선택합니다.
- 체크박스로 한 번의 전송 대상 탭을 고릅니다.
- 현재 화면 상태를 일회성으로 보냅니다.
- 점수판 버튼의 명칭은 항상 "점수판"이며 활성 상태만 시각적으로 표시합니다.

## 7. 객체 관리 및 기존 기능 보존
- 원본 파일이 없어도 이미지 객체를 선택·이동·삭제할 수 있습니다.
- 우클릭 메뉴에서 객체 이름을 변경할 수 있습니다.
- 다중 선택 일괄 이름 변경은 (1), (2), (3) 형식으로 부여합니다.
- 파일 관리 목록에는 객체 종류와 이름을 표시합니다.
- 우클릭 메뉴 상단에 현재 객체 이름을 표시합니다.
- 6.1에 있는 필기, 텍스트, 도형, 페이지, 점수판, 저장/불러오기, PDF, 클립보드, 확대/축소, 배경, 툴바 기능을 보존합니다.

## 8. 데이터 호환성 및 안전
- 기존 6.1 Firebase 공유 칠판의 데이터와 기기 연결 정보를 확인하고 승계합니다.
- 서버 스키마 변경은 버전 필드와 마이그레이션 경로를 마련한 뒤 적용합니다.
- 로컬 DB는 경로 기반 키를 사용해 6.1과 분리합니다.
- 정본 교체 전 서버/후보 백업을 생성하고 복구 절차를 제공합니다.
- 동시 정본 선택, 업로드 재시도, 중간 연결 끊김, 부분 배포, 오프라인 기기 복귀를 검증합니다.
- 기존 6.1에서 사용하는 Firestore 규칙과 신규 후보 저장 권한을 별도 검토합니다.

## 9. 검증 계획
- 6.1 기존 Firebase 데이터로 6.2 접속 및 읽기 호환 확인.
- 서버 모드 기본 실행 및 실시간 다중 탭/기기 공유.
- 네트워크 단절 후 로컬 전환/전환 거부.
- 여러 기기 각각 로컬 모드에서 작업.
- 각 기기 최종 스냅샷 임시 제출.
- 같은 데이터 그룹핑 및 다른 데이터 후보 분리.
- 후보 열람/편집/지문 재계산.
- 서버/기기 후보 중 최종 정본 선택 및 전체 배포.
- 확정 실패 시 후보/백업 보존.
- 확정 성공 후 비선택 후보 정리.
- 장기간 오프라인 기기 재접속 시 최신 정본만 즉시 복원.
- 이미지/PDF 수동 P2P 파일 확보 및 누락 객체 관리.
- 정상 온라인 애니메이션 동시 재생, 백그라운드 진행, 복귀 시 과거 재생 방지.
- 음향 세 가지 정책 검증.
- 기기/탭 이름, 탭 번호 재사용, 대기/오프라인 상태 검증.
- Windows Edge, Chrome, Android 삼성 브라우저, 태블릿, 전자칠판 실기기 검증.

## 11. 구현 전 반드시 설계할 기술 항목
1. Firestore 스냅샷 임시 저장 구조와 1 MiB 문서 크기 제한 대응.
2. 정규화 JSON의 결정적 직렬화와 SHA-256 계산 범위.
3. 후보 편집을 위한 격리 저장소 및 미리보기 로딩 방식.
4. 정본 승격의 원자성, 버전 잠금, 동시 확정 방지.
5. 기존 Firestore rules의 후보 읽기/쓰기 권한과 보안.
6. 오프라인 후보 업로드와 중복 제출 방지용 candidate ID.
7. 후보가 참조하는 IndexedDB 파일을 P2P로 확보하는 흐름.
8. 서버 시간과 단말 로컬 수정 시각의 신뢰도/정렬 정책.

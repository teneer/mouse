# 만능칠판 6.2 — 차기 개발 작업판

## 프로젝트 운영 원칙
- 개발 경로: `/만능칠판6.2/`
- 기준 소스: `/만능칠판6.1/`의 2026-11-18 기준 main 커밋 `81a2414de8d74288e8ece156faecf2f28efa9413`
- `/만능칠판6.1/`, `/만능칠판-test/`, `/만능칠판6.0/` 원본은 수정하지 않습니다.
- 기존 기능을 임의로 삭제하거나 단순화하지 않습니다.
- 기존 Firebase 학급 데이터와 호환되도록 같은 Firebase 프로젝트 및 기존 공유 칠판 ID를 승계하는 것을 기본으로 합니다. 새 데이터 구조를 적용할 때는 마이그레이션 및 하위 호환성을 먼저 검토합니다.
- 6.2는 6.1의 복사본에서 출발한 개발판입니다. 복사만으로 6.2 신규 설계가 구현된 것은 아닙니다.

## 6.2 핵심 개발 방향
1. 서버 모드를 기본으로 사용합니다.
2. 연결이 끊기면 사용자에게 현재 상태를 로컬 모드로 전환할지 묻습니다.
3. 여러 기기가 각각 독립적으로 로컬 모드로 작업할 수 있습니다.
4. 온라인 복귀 시 각 기기의 작업 이벤트를 누적 전송하지 않고 최종 데이터 스냅샷만 서버 임시 후보로 제출합니다.
5. 동일한 데이터 후보는 SHA-256 지문으로 묶고, 보유 기기·서버 및 마지막 수정 시각을 표시합니다.
6. 사용자는 후보를 열람·편집한 뒤 하나를 최종 정본으로 선택합니다.
7. 최종 정본을 서버와 온라인 기기에 배포하고, 성공 확인 후 비선택 임시 후보를 정리합니다.
8. 이미지/PDF 바이너리는 기존 IndexedDB + 수동 P2P 전송을 유지합니다. 자동 업로드·다운로드·Firebase Storage 보관은 하지 않습니다.

상세 요구사항과 미확정 기술 항목은 [6.2 개발 명세](6.2-개발명세.md)를 참고합니다.

## 데이터 저장 범위
- 이 폴더는 URL 경로가 `/만능칠판6.2/`이므로 IndexedDB 이름과 localStorage 키에 경로를 포함하는 기존 구조에서는 6.1 로컬 데이터와 분리됩니다.
- Firebase 서버 데이터는 같은 프로젝트/공유 칠판 ID를 사용하면 기존 6.1과 공유됩니다. 따라서 서버 스키마 변경은 6.1과의 호환성 확인 후 적용해야 합니다.
- 이미지/PDF 실제 파일은 각 기기의 IndexedDB에 남으며, 공유 데이터 후보에는 파일 참조·메타데이터를 포함하되 바이너리를 서버에 자동 복사하지 않습니다.

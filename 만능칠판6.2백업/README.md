## 6.2 핵심 개발 방향

### 온라인 협업
1. 서로 다른 객체는 여러 기기에서 동시에 편집할 수 있습니다.
2. 같은 객체는 마지막으로 클릭한 기기가 제어권을 가져갑니다. 기존 기기는 해당 객체의 선택과 편집 핸들이 해제됩니다.
3. 객체가 선택된 동안 제어권을 유지하고 주기적으로 갱신합니다. 선택 해제·페이지 이동·편집 종료 시 해제하며, 임대 만료는 비정상 종료 등 갱신 중단 시 회수에 사용합니다.
4. 같은 객체의 텍스트 편집 중 제어권 이전이 요청되면 기존 입력을 강제 완료하고 서버 확정한 다음 새 기기에 넘깁니다.
5. 객체/페이지 삭제는 서버 확정 즉시 모든 온라인 기기에 반영하며, 지연된 과거 편집 요청으로 삭제 대상이 부활하지 않게 합니다.
6. 점수 증감과 공유 되돌리기는 서버 확정 순서로 처리합니다. 직접 수정과 증감이 동시에 발생하면 직접 수정이 먼저 확정되고, 겹친 증감은 새 기준값에 이어 적용합니다.

### 연결 단절과 로컬 모드
1. 기본은 서버 모드입니다.
2. 서버 모드에서 연결이 끊기면 편집을 차단하고 "오프라인에서는 편집할 수 없습니다. 잠시 후 다시 시도해주세요."를 표시합니다.
3. 연결 단절 전에 생성된 서버 전송 요청은 동일 작업 ID로 재시도하지만, 연결이 끊긴 뒤 새로운 편집 요청은 만들지 않습니다.
4. 사용자가 로컬 모드를 선택해야 현재 상태를 독립 로컬 작업 공간으로 복사하고 편집할 수 있습니다. 이때 미확정 서버 전송은 취소합니다.
5. 여러 기기가 각각 독립적으로 로컬 모드에서 작업할 수 있습니다.
6. 로컬 모드로 재연결하면 해시를 먼저 비교합니다. 서버/기존 후보와 같은 데이터는 스냅샷을 다시 올리지 않고, 새로운 데이터만 최종 스냅샷 후보로 제출합니다.
7. 동일 데이터는 하나의 선택지로 묶습니다. 사용자는 후보를 열람·편집하고 최종 정본을 선택합니다. 확정 성공 후 비선택 후보를 정리합니다.

### 파일과 기타 기능
- 이미지/PDF 바이너리는 기존 IndexedDB + 수동 P2P 전송을 유지합니다. 자동 업로드·다운로드·Firebase Storage 보관은 하지 않습니다.
- 점수 애니메이션은 온라인 중 모든 탭에서 같은 시간축으로 진행하며, 복구/정본 교체 시 과거 연출을 재생하지 않습니다.
- 기기 관리는 더보기, 탭 관리는 화면 전송 메뉴에서 합니다.
- 화면 상태 전송은 대상 탭을 선택해 일회성으로 수행합니다.

상세 요구사항과 미확정 기술 항목은 [6.2 개발 명세](6.2-개발명세.md)를 참고합니다.

## 데이터 저장 범위
- 이 폴더는 URL 경로가 \`/만능칠판6.2/\`이므로 IndexedDB 이름과 localStorage 키에 경로를 포함하는 기존 구조에서는 6.1 로컬 데이터와 분리됩니다.
- Firebase 서버 데이터는 같은 프로젝트/공유 칠판 ID를 사용하면 기존 6.1과 공유됩니다. 따라서 서버 스키마 변경은 6.1과의 호환성 확인 후 적용해야 합니다.
- 이미지/PDF 실제 파일은 각 기기의 IndexedDB에 남으며, 공유 데이터 후보에는 파일 참조·메타데이터를 포함하되 바이너리를 서버에 자동 복사하지 않습니다.

## 구현 및 테스트 상태 (2026-11-18)
### 1차 코드 반영
- 객체별 제어권 요청/갱신/해제 경로를 실제 캔버스 선택 및 저장 흐름에 연결했습니다.
- 같은 객체의 제어권 이전 요청을 기존 소유 탭에서 수신하면 텍스트 입력을 강제 완료하고 저장을 기다린 뒤 제어권을 넘기도록 연결했습니다.
- 제어권을 잃은 기기는 해당 객체 선택을 해제하도록 처리했습니다.
- 서버 모드에서 연결이 끊기면 캔버스 조작을 막고, 진행 중 텍스트 입력을 완료해 기존 서버 전송 대기 흐름에 보존하도록 했습니다.
- 객체 잠금 문서 ID의 충돌 가능성을 제거하고 관련 단위 테스트를 보강했습니다.
- Firestore 보안 규칙에 `objectLocks` 접근 규칙을 추가했습니다.

### 아직 구현하지 않은 범위
- 서버 모드 오프라인 중 로컬 모드로 전환하는 전용 UX 및 독립 작업 공간
- SHA-256 스냅샷 후보 제출, 동일 해시 그룹화, 후보 열람/편집, 최종 정본 선택 및 배포
- 점수 직접 수정 우선 규칙의 서버 확정 로직
- 전체 작업 순서 기반 공유 되돌리기의 추가 통합 검증
- 온라인 다중 기기 및 브라우저 실기기 회귀 검증

### 배포/검증 주의
- 변경된 `firestore.rules`는 GitHub에 반영된 파일일 뿐 Firebase 프로젝트에 자동 게시되지 않습니다. 실제 다중 기기 테스트 전에 Firebase Console에서 해당 프로젝트의 Firestore Rules를 검토·게시해야 합니다.
- 현재 환경에서는 브라우저 실기기 검증과 `npm test` 실행을 완료하지 않았습니다. 기존 테스트 통과를 주장하지 않습니다.
- 6.1에서 가져온 테스트 결과를 6.2의 통과 결과로 간주하지 않습니다.
